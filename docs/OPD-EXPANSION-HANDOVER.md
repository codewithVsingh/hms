# OPD expansion and portal PWA handover

## Scope and status

This is the consolidated development source, not a production-certified medical system. All earlier code is included. New migrations are additive, 011-016; no live Supabase/Razorpay credentials are included. New provider adapters default off. Use an isolated staging environment and fictional patients. The application must not accept live patients, payments or issue clinical documents until the acceptance tests, healthcare legal/clinical review and backup recovery verification are completed.

### Implemented in this release (source code, live verification pending)

- Portal-only manifest, PNG/maskable/apple icons, install prompt and iOS instructions. Network-only navigation service worker; no Cache API writes, no offline medical records, and no background retry of clinical writes. Generic offline fallback. Website has no manifest/registration.
- Assigned-clinician record timeline (within the doctor's branch/assignment), versioned notes inherited from the earlier release, diagnosis/history/allergy entries, vitals, prescription item builder, clinician attestation and immutable issued version, patient release, follow-up date and print layout. Attestation is NOT a legally certified electronic signature.
- Patient portal self-owned released prescriptions, invoice summaries, released documents, opt-in contact preferences. Appointment history and payment from the earlier release; same-doctor reschedule and invoice print added. Patient demographic corrections by reception, without changing identity links or verified contacts.
- Same-doctor rescheduling within a branch, unchanged original invoice/fee, deterministic row locks, conflict detection, audited old/new slot. No automatic change-doctor or fee changes. No uncertain/refunded payment moves.
- Branch/day OPD token counter, token list, doctor leave blocking with appointment-conflict guard, scheduled slot generation. Move/cancel existing bookings manually before leave; no emergency auto-cancel.
- Private clinician document uploads, file type/signature and 4 MB limit, private approved scanner required, private storage and one-minute authorized download links, release to patient and audit. No patient-side upload yet. A scanner with DPA and approved hosting is essential; do not send medical data to unapproved external scanners. Vercel request body constraints motivated the 4 MB API cap.
- Staff invitations (non-doctors), role replacement for branch memberships, self-edit guard, removing all roles revokes branch operation access, recovery and reset screens. Initial doctor and administrator onboarding requires verified registration/provisioning; existing identity linking and invite failure recovery are manual.
- Opt-in transactional notifications: confirmations, cancellations, rescheduling, 24h/1h reminders, payment/refund and released prescription events; queued through SQL triggers; Resend, Twilio and Meta template adapters. Verified contacts only. Messages contain no patient name, diagnosis or treatment details. Provider acceptance is not delivery; ambiguous sends are dead-lettered for review; 429 retries are limited. Opt-in applies to future events; no retroactive confirmation of first booking by default.
- Read-only Razorpay recovery worker for known orders/refunds, no automatic new charge/refund creation. Unattached or old order claims and ambiguous refund submissions require manual review. The earlier full-refund workflow is retained.
- Date-range visit and collection aggregates with CSV export; invoice print/save-as-PDF and receipt view via browser print. Gross captured is not accounting revenue or bank settlement. Refund totals grouped by request date. No independent PDF binary generator or certified signature.
- CAPTCHA-gated public callback form, public website contact link, staff/admin inquiry status workflow. Server-only portal endpoint with exact origin, CAPTCHA hostname validation and per-phone limit. No health-condition free-text input; no marketing pixels. Existing WhatsApp click-to-chat, website SEO/CMS, and Razorpay integration retained.

### Deferred or incomplete (do not treat as complete)

- Certified digital signatures, prescription amendments/voiding and final encounter signing; full cross-doctor longitudinal chart subject to explicit consent/access, structured clinical templates, medicine catalog, nurse delegation, referrals, medical certificates and lab requisitions. Review prescribing/record-retention law and workflow before enabling clinical use.
- Full document lifecycle (patient uploads, scan result webhook, access log monitoring, backup/restore, document versions and orphan cleanup), dependent/guardian verification, safe patient linking/merge, duplicate detection, self profile editing, consent export/correction/erasure, clinical feedback.
- Partial payments/refunds, advances/discounts, tax rules, line-item editing, offline refunds, settlement bank reconciliation, expenses and accounting exports. Automatic recovery only for known provider identifiers; manual review remains required. Refund delivery webhooks and formal financial reconciliation remain incomplete.
- Custom role definitions and permission editor, doctor credential onboarding UI, explicit account deactivation/session revocation, branch switcher and broader configuration settings. Existing role assignment edits do not invalidate Auth tokens immediately; DB permissions are rechecked on each authorized operation.
- Automated messaging requires actual provider configuration, DLT/template approvals, an approved schedule, delivery callbacks/status reconciliation and an operational retry review process. Web Push is not implemented. PWA installation and safe offline fallback do not imply full offline clinical access.
- Full marketing suite: multilingual content, campaign attribution and UTM reporting, cookie consent, SEO monitoring, approved ads, campaign tools, accessibility audit. Technical SEO and CMS remain as before; no ad/analytics tracking of clinical data.
- Scheduled maintenance is implemented as a protected HTTP endpoint; schedule it explicitly. Railway worker optional. Default all integrations disabled. No real payment, OTP, messaging, scanner, or E2E environment validation here. Full Next.js type check/build cannot be run in this environment due to unavailable package installation; SQL not executed against PostgreSQL.
- IPD, pharmacy, laboratory, inventory, insurance, teleconsultation and ABDM remain future modules. Initial architecture remains single-branch OPD-first.

## How to review on mobile without setup

Open `review/HMS_Mobile_Review.html` in a browser with JavaScript enabled. Use the View selector. This self-contained file includes embedded CSS, demo components and a lightweight compatibility adapter for the locally available React 16 runtime (not the production React 19 runtime). It contains no network integrations, no real patient records and no live payments; sample data resets on navigation. The preview is not an installable PWA itself. Some messaging/file/preview-app viewers do not execute scripts; download and open the HTML in a browser, or view `review/screenshots/`. Use the actual Next.js portal on HTTPS/localhost to verify browser installation.

## Integration order

1. New Supabase staging project: apply all migrations `202611240001` to `202611240016` in lexical order; existing DB at migration 010: apply only 011-016 if original checksums match. Do not re-run CREATE statements. Follow `supabase/README.md`; run all three verify scripts. Review backups and private storage policies.
2. Initial hospital, approved doctor registration number, admin and receptionist: use `supabase/setup/01_provision_hospital.sql` after creating Auth users. No default real credentials. Keep online booking and payments disabled until staging verification.
3. Node 22 + pnpm 10.11, `pnpm install`, `pnpm typecheck`, `pnpm build`, `pnpm test:security`, `pnpm test`. Resolve any true build or database errors before deployment. `pnpm dev` starts website 3000 and portal 3001.
4. Use both `.env.local.example` files. Portal alone has secret/service role keys. Host public site and portal on different origins. Update approved hospital details, policies, emergency number, phone and WhatsApp. Keep indexing, payments and notification providers off until verified.
5. Supabase Auth: enable CAPTCHA, configure verified phone SMS, MFA, rate limits, secure password policy. Add portal `/auth/callback` and `/auth/confirm` URLs to redirect allowlist. Customize invitation and recovery email templates to use the actual portal origin, e.g. `https://portal.example.in/auth/confirm?token_hash={{ .TokenHash }}&type=invite` or `type=recovery` (use correct Supabase template variables and verify in staging). Callback supports PKCE code exchange on same initiating browser; token-hash confirm supports email recovery/invite on another device. Test expiry, replay, URL log scrubbing and secure password changes. Disable public staff signup. Verify staff invitation/DB link partial-failure workflow manually.
6. Razorpay test mode + webhook, verify capture and refunds against real sandbox. `HMS_RECONCILIATION_ENABLED=true` only after sandbox success; it checks known provider identifiers, never initiates new payments/refunds. Review aged and ambiguous claims manually.
7. Background worker: call GET `/api/internal/maintenance` with `Authorization: Bearer <CRON_SECRET>` from an approved scheduler, e.g. every 5-15 minutes (choose plan/provider supporting cadence). Generate a long random secret, no query-string secret. Endpoint performs slot generation, due opt-in jobs and optional payment reconciliation. On Vercel select appropriate function max-duration and plan; do not assume a free plan supports frequent cron. Use Railway/another controlled worker if needed. Monitor result counts and dead-letter jobs. Do not deploy active worker in demo or send test messages to real patients.
8. Notify providers: enable one channel at a time. Resend verified sending domain; Twilio approved Indian SMS route, sender/template/DLT where required; WhatsApp Cloud API approved business number, token, graph version, and approved templates without parameters. Map JSON keys `appointment_confirmed`, `appointment_changed`, `appointment_cancelled`, `reminder_24h`, `reminder_1h`, `payment_received`, `refund_processed`, `record_available`. Configure contact consent and test on allowlisted synthetic accounts first. Only enable channels for approved operational use.
9. Medical scanner: private HTTPS endpoint controlled by/approved for hospital data; accepts application/octet-stream authenticated by bearer token; responds `{"clean":true}` only for safely scanned content. A missing/failed scanner refuses upload. Confirm retention, deletion, storage backup and signed-link expiry. Vercel limit is 4 MB in this API; use an audited larger-file workflow later.
10. Callback: configure website public Turnstile site key and portal `HMS_CALLBACK_TURNSTILE_SECRET`, `HMS_CALLBACK_ENABLED=true`, exact website origin. Keep no service role key in website environment. Verify the actual website hostname with Turnstile. Do not collect medical details or run marketing on callback information.

## Acceptance criteria before real use

- Real production build, full TypeScript type check, migrations on isolated Supabase and grant/RLS assertions, test data provisioning, backup and restore.
- Test all API and direct RPC paths for anonymous, patient, receptionist, billing, assigned doctor, unassigned doctor, disabled membership, AAL1 and cross-branch access; verify clinical timeline and document scope; role revocation immediately denies further API calls.
- Concurrent same-slot bookings/reschedules; leave races; same-day queue uniqueness; timezone boundaries; cancellation and uncertain/late/duplicate Razorpay capture; multiple webhook delivery; payment/refund recovery; no duplicate payment or invoices.
- Prescription builder and attestation, duplicate issuance rejection, correct medical registration, release and patient identity; final signed document requirements review; print and download; scanner rejects malicious content, invalid magic/size, unauthorized documents, expired signed URLs and public storage access.
- Invitation links and password reset cross-device and replay tests, MFA recovery and access review, all workflows with multiple staff roles.
- Provider test sends, consent withdrawal before claim, opt-out, 429 retries, unknown delivery, job reprocessing/duplicate prevention, scheduler failures, template approval and provider callbacks (not implemented). Operational monitoring and manual fallback.
- Android Chrome, iOS Safari, desktop Chromium/Firefox/Edge: install, launch, update, logout, offline fallback, no cached sensitive API/document responses or background mutations; accessibility, keyboard, print and low-network tests.
- Medical, legal, security and finance signoff; emergency downtime procedure, staff training, data protection and health privacy review.
