**Priority:** P0 critical (security, patient safety, payments, data integrity) · P1 needed before launch · P2 important improvement · P3 optional.
**Status:** Implemented = changed in this branch and verified by tests · Fixed on main = fixed in an earlier commit to `main` · Pending · Blocked = needs credentials, infrastructure or a business decision.

The live status of each item is tracked in [IMPLEMENTATION_TRACKER.md](IMPLEMENTATION_TRACKER.md).

## Verified as already correct

These parts of the brief were checked and found already in place, most of them now proven by the database tests:

- Browser roles cannot use the `hms` or `hms_private` schemas. There are no table grants to `anon` or `authenticated`, and RLS is enabled on every `hms` table.
- Only four functions are callable anonymously: catalog, slots, public content and the cancellation policy.
- All 55 signed-in RPCs check permission or ownership internally.
- Every SECURITY DEFINER function pins `search_path`.
- Staff functions require MFA (`aal2`).
- Nobody can change their own roles, invites cannot grant admin, and role changes are audited.
- Booking: server-side fee, policy-version acknowledgement, idempotent request IDs, one live appointment per slot (unique index), slot row locks, a 10-minute hold, and per-account booking limits.
- Payments: orders created on the server with the server amount; one order per invoice; signature verification over the raw body (constant time); amount and currency re-checked against Razorpay; duplicate webhooks de-duplicated; captures arriving after the hold expired go to reconciliation instead of confirming.
- Cancellation: the quote is calculated on the server; client amounts must match exactly; it is idempotent; the policy is snapshotted per booking; refunds are claimed once, provider results must match the stored amount, and the admin path cannot turn a partial refund into a full one.
- Manage booking requires a verified mobile session and ownership. A reference plus a name or UHID alone is not enough.
- File uploads: size limit, magic-byte type check, a mandatory HTTPS malware scanner, a private bucket, random storage paths, and 60-second signed download URLs after an access check.
- PWA: portal only; nothing cached; generic offline page; the website does not register a service worker.
- Callback form: origin check, Turnstile verified server-side with a hostname check, no reflected data.
- Security headers on both apps; the portal sends `noindex`; API responses are `no-store`.
- No credentials found in the full git history; no known vulnerable production dependencies (`pnpm audit`).
